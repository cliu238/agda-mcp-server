## Additional Accuracy Findings (beyond the `agda_*` tool-name scan)

Two files contain a reference that is stale in a way the tool-name regex cannot catch — both surfaced by the required full read-through, not the scan itself.

**1. `docs/literate-agda-assessment.md` — stale capability claims, not stale tool names.**

The doc's "What Does Not Work" table asserts:

> Module discovery (`agda_list_modules`) — Hardcoded `.agda` filter in `src/tools/file-tools.ts`
> Definition search (`agda_search_definitions`) — Same hardcoded filter
> Test coverage for literate formats — No `.lagda*` fixtures exist

All three claims are false against current `HEAD`, verified directly this session:

- `src/agda/data/agda-source-extensions.json` is the actual SSOT (`file-tools.ts` is a barrel that delegates to it, per its own header comment: "for the source-extension filter. The actual callbacks live in...") and already version-gates all 7 literate suffixes: `.lagda` (2.5.1+), `.lagda.tex`/`.lagda.md`/`.lagda.rst` (2.5.3+), `.lagda.org` (2.6.1+), `.lagda.tree`/`.lagda.typ` (2.7.0+) — the last two are formats this assessment doc never even anticipated.
- A full `src/session/literate/` extraction subsystem exists (`detect-format.ts`, `extract-fenced.ts`, `extract-org.ts`, `extract-rst.ts`, `extract-latex.ts`, `extract-tree.ts`).
- 7 dedicated fixtures exist: `test/fixtures/agda/Literate{Markdown.lagda.md,Latex.lagda,TexExplicit.lagda.tex,Org.lagda.org,Rst.lagda.rst,Tree.lagda.tree,Typst.lagda.typ}`.

Unlike `docs/release-0.7.0-triage.md`, this doc was never reconciled after its recommendations shipped — no "Reconciliation" section, no status update. See Cut-List Candidates below.
