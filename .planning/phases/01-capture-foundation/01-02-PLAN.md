<objective>
Complete CAP-01's replay-manifest fidelity requirement, which Plan 01-01
deliberately stubbed (mergedArgv: [], agdaDirContents: null, buildMode: "unknown",
importClosureHash: null, inlinedFirstPartySources: []). This plan makes every one
of those five fields real: the ordered pre-dedup argv (duplicates preserved), the
realized AGDA_DIR contents read from the live singleton (never re-derived), a
fresh-vs-shared _build heuristic, a sha256 content-hash over the loaded file's
full transitive import closure, and the full text of every first-party file in
that closure inlined per D-07 (so a second machine can replay without the
original checkout - third-party library files are pinned via the manifest, never
inlined).

Purpose: without this, a captured manifest cannot be replayed faithfully -
CAP-01's whole point is that the oracle triad (Phase 2) can pin to an exact,
reproducible environment.
Output: `session.lastDispatchedLoadArgv` field + population point in
`session.ts`; a fully-fidelity `buildReplayManifest()`; a new
`import-closure-hash.ts` module.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Loaded Agda source tree -> import-closure-hash.ts | Source files under the project root are semi-trusted (agent/dogfooding-project-controlled, not server-controlled) |
| Realized AGDA_DIR on disk -> manifest-builder.ts | Files at session.libraryRegistration.agdaDir are process-local temp/stable dir contents, not directly caller-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02-01 | Denial of Service | import-closure-hash.ts reading arbitrary closure files | mitigate | Per-file 512 KiB cap (mirrors MAX_AGDA_SOURCE_BYTES) before any readFileSync; oversized files contribute a placeholder marker instead of their bytes, never an unbounded read |
| T-02-02 | Tampering | readRealizedAgdaDir path construction | mitigate | agdaDir comes only from session.libraryRegistration (server-derived, either a mkdtempSync path or a validated existsSync+isDirectory AGDA_DIR env value) - never from tool caller input in this plan |
| T-02-03 | Information Disclosure | importClosureHash / inlinedFirstPartySources leaking file paths and full source text | accept | The manifest already needs the closure file list and inlined source for D-07's replay-fidelity requirement; paths are repo-relative, not absolute; the manifest (including inlined sources) is staged out-of-repo under .agda-mcp/captures/ and never returned to the MCP caller in this plan (Plan 01-01's CaptureReference has no manifest field) |
| T-02-04 | Denial of Service | inlineFirstPartySources reading unbounded closure file content into memory | mitigate | Same 512 KiB per-file cap as hashImportClosure; oversized files are excluded (not truncated/faked) and listed separately, so a pathological closure cannot exhaust memory or corrupt a replay with fabricated content |

</threat_model>
