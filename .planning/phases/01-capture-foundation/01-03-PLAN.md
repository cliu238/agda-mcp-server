<objective>
Implement CAP-04's recorded session action log: a bounded ring-buffer recorder
that captures ordered `{tool, args, timestamp, normalizedResponse}` triples at
the MCP tool-call boundary, gated by `AGDA_MCP_CAPTURE=1` (default OFF, per
D-06), zero-cost when disabled. This plan builds the recorder as a fully
self-contained module with no dependency on `register-capture-session.ts` -
Plan 01-05 performs the final wiring that drains this buffer into the staged
`CaptureArtifact`.

Purpose: without an always-on-when-enabled recorder, a surprise defect (the
common case per D-05) would produce an empty action log exactly when it matters
most - the recorder must already be running before the agent knows there is a
problem.
Output: `src/agda/session-capture/recorded-transport.ts`, one new call site
inside `src/tools/tool-registration.ts`'s `timedCallback`.
</objective>

```
const timedCallback = async (toolArgs: any) => {
  const startMs = performance.now();
  let result: unknown;
  try {
    result = await args.callback(toolArgs);
  } catch (err) {
    result = makeTextToolErrorResult(args.name, err, {});
  }
  const elapsed = Math.round(performance.now() - startMs);
  if (result && typeof result === "object" && "structuredContent" in result) {
    const structuredContent = (result as any).structuredContent;
    if (structuredContent && typeof structuredContent === "object" && structuredContent.elapsedMs === undefined) {
      structuredContent.elapsedMs = elapsed;
    }
  }
  return result;
};
```
This is the single hook point: after `structuredContent` is available (it is the
normalized `ToolEnvelope`), call the new recorder before `return result;`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| MCP tool args -> recorded-transport.ts buffer | Tool args are agent-supplied and may contain large strings (e.g. beforeSource in later plans); the buffer holds references in memory only, never writes to disk in this plan |
| AGDA_MCP_CAPTURE env var -> recorder activation | Process-level env var, not caller-controlled per-call - an agent cannot enable/disable recording via a tool argument |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-03-01 | Denial of Service | recorded-transport.ts unbounded memory growth | mitigate | MAX_RECORDED_ACTIONS=2000 hard cap with drop-newest-once-full; no per-action size cap in this plan (args/normalizedResponse can still be large) - flagged as a follow-up if Phase 2/3 dogfooding shows memory pressure, tracked informally, not a new requirement |
| T-03-02 | Information Disclosure | recorded actions retaining tool args in memory | accept | Args are only ever drained by the capture tool (same process, same trust boundary) or discarded; this plan does not persist or transmit the buffer anywhere |
| T-03-03 | Tampering | A malicious tool callback forging structuredContent shape | accept | recordAction's shape guard (typeof === "object") only prevents a crash on unexpected shapes; deeper validation is out of scope - the recorder is a diagnostic aid, not a security boundary |

</threat_model>
