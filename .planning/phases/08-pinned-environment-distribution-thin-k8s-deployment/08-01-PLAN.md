## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| teammate machine -> GitHub | `clone-fuel-corpora.mjs` clones 2 public + 2 private repos over HTTPS; a private-repo token, if present, travels in the clone URL |
| installer -> local filesystem | writes `tooling/scripts/run-pinned-agda.sh` (executable) and invokes `npm ci` (arbitrary package-manager lifecycle scripts) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | clone-fuel-corpora.mjs git/gh invocations | mitigate | Every subprocess call uses an argv array with `shell: false` — never a shell-interpolated string (CWE-78 discipline, matching `upload-run.mjs`'s own `spawn` convention) |
| T-08-02 | Information Disclosure | private-repo clone token | mitigate | Token is read from `GH_TOKEN`/`GITHUB_TOKEN` env or an already-authenticated `gh` session — never printed, logged, or written to any file; on absence the corpus is skipped, never silently retried with a hardcoded fallback credential |
| T-08-03 | Elevation of Privilege | `runNpmCi` executing `npm ci` (arbitrary lifecycle scripts from package-lock.json) | accept | `package-lock.json` is already a tracked, reviewed artifact of this repo; `npm ci` here runs the SAME dependency set every `npm run build` already runs locally and in CI — no new package is introduced by this plan (zero `npm install <new-pkg>` anywhere in this phase) |
| T-08-04 | Tampering | `run-pinned-agda.sh` generation | mitigate | The wrapper's only content is a fixed `exec "<verified-agda-path>" "$@"` template — the resolved path is written verbatim from `locateAgdaBinary`'s own `which`/`AGDA_BIN` result, never teammate-supplied free text interpolated unescaped into a template with other content |
</threat_model>
