## Phase Goal

**As a** maintainer or AI agent (Codex/Claude Code) dogfooding the Agda MCP server, **I want to** get
a captured session judged "true green" only when all three oracle predicates — the server-faithfulness
differential, the soundness-hygiene scan, and the conformance proxy — agree, **so that** a fresh
`agda` re-run's necessarily-insufficient pass is never mistaken for proof the server told the truth,
the fix was sound, and the right theorem was actually proved.

<objective>
Build ORCL-03: the advisory conformance proxy that alpha-diffs the proven `Cmd_infer_toplevel`
signature against the capture's task-authored expected signature (CAP-05), flagging narrowing /
added-premises / renames / target edits for human review. Never a hard gate — this predicate can only
add advisory signal, never fail a capture.

`Cmd_infer_toplevel` requires a file already loaded in the calling session's scope (verified in
RESEARCH.md's Pitfall 7 via direct code read of `expression-operations.ts`'s `requireFile()` call) —
so this predicate's `judgeOrcl03` performs its OWN cold `Cmd_load` (reusing Plan 02-03's
`materializeCaptureEnvironment`) before issuing `Cmd_infer_toplevel` on the SAME session, and its
lower-level `runColdInferAndCompare` accepts an ALREADY-loaded session so Plan 02-05's composed CLI
can share ONE cold process between ORCL-01 and ORCL-03 (avoiding a second full cold compile on large
corpora, where a from-scratch recompile can itself approach a practical timeout).

Purpose: A fresh cold compile (ORCL-01) proves the server told the truth about what Agda would say —
it says nothing about whether the RIGHT statement was proved. This is the one predicate aimed at the
narrowed/wrong-statement failure mode the real agda-unimath/Hopf dogfooding makes first-class.
Output: A complete, standalone-runnable `scripts/oracle/orcl-03-conformance.mjs` reporting
`consistent` / `conformance-flagged` / `vacuous-no-expected-signature`, always advisory.
</objective>

From src/agda/session-capture/artifact-types.ts:
  `OracleSubstrate.expectedSignature: string | null` — CAP-05's task-authored expected top-level
  signature, read from `artifact.oracleSubstrate.expectedSignature`.

Design decision this plan adopts (the artifact contract does not itself specify a parsing
convention — document this choice in the code as a scoped, isolated function): `expectedSignature` is
parsed as `<name> : <type>` by splitting on the FIRST top-level `:` (a colon not nested inside `(`,
`{`, or `[`) — the trimmed substring before it is the `Cmd_infer_toplevel` target name; the trimmed
substring after it is the expected type string to alpha-diff against the inferred type. If no
top-level `:` is found, treat the ENTIRE trimmed string as both the target name AND (degenerate) the
expected type, so a bare name still resolves a `Cmd_infer_toplevel` target.

From src/protocol/command-builder.ts (tsx-importable):
  `modeTopLevelCommand(name, mode, ...parts)` — call as
  `modeTopLevelCommand("Cmd_infer_toplevel", "Normalised", quoted(targetName))`, matching the EXACT
  rewrite-mode convention `src/agda/expression-operations.ts`'s `inferTopLevel` already uses for every
  other infer/compute command in this codebase.
  `iotcmEnvelope(filePath, innerCommand)`.

From src/protocol/responses/expression-display.ts (tsx-importable):
  `decodeExpressionDisplayResponses(responses: AgdaResponse[]): { normalForm: string; inferredType:
  string }` — a pure response-shape decoder with no live-session (`ctx`) dependency, safe to reuse for
  the cold `Cmd_infer_toplevel` response.

RESEARCH.md Pitfall 8 (read before implementing the compare function): there is NO known Agda flag to
disable `DISPLAY`-pragma / pattern-synonym pretty-printing, so two semantically different types can
print identically or vice versa. This is why D-02/D-06 keep ORCL-03 permanently advisory. Per
RESEARCH.md's Open Question 1 recommendation: implement the SIMPLEST viable comparison first
(whitespace-normalized string equality) rather than a token-canonicalization pass — treat deeper
canonicalization as a future empirical follow-up, not something to build without real data.
