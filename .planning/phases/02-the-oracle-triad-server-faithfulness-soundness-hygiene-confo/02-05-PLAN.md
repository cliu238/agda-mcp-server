## Phase Goal

**As a** maintainer or AI agent (Codex/Claude Code) dogfooding the Agda MCP server, **I want to** get
a captured session judged "true green" only when all three oracle predicates — the server-faithfulness
differential, the soundness-hygiene scan, and the conformance proxy — agree, **so that** a fresh
`agda` re-run's necessarily-insufficient pass is never mistaken for proof the server told the truth,
the fix was sound, and the right theorem was actually proved.

> native "As a / I want to / so that" form. The story above is a faithful reformatting of that exact
> goal (same actors, same capability, same outcome — no new scope), not an invented one. Run
> `/gsd mvp-phase 2` if you want ROADMAP.md's own Goal line rewritten to match.

<objective>
Compose the three independently-shippable predicates (Plans 02-02/02-03/02-04) into the ONE verdict
the rest of the milestone consumes: a single CLI entry point that runs ORCL-01/02/03 (sharing one
materialized environment and one cold Agda process between ORCL-01 and ORCL-03), composes the D-02
outcome schema, writes a verdict sidecar next to the capture, and records the abstention/INCONCLUSIVE
rate as a first-class metric.

This is the final, most user-visible slice of the phase: "the maintainer/agent runs ONE command
against a staged capture and gets the complete, composed Oracle Triad judgment."

Purpose: ROADMAP success criterion 5 requires this composition be explicit — ORCL-01 passing is
necessary but insufficient; only all three predicates together justify "true green", and ORCL-01's
cold result becomes the correct expected value Phase 3's regression emitter reads.
Output: `scripts/oracle/verdict-schema.mjs` (the shared contract) and `scripts/oracle/run-oracle.mjs`
(the composing CLI), both tested end-to-end against a real capture.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| User-supplied `artifactPath` CLI argument -> verdict sidecar write path | The sidecar path is derived from the argument, not from artifact-internal (attacker/agent-influenceable) content |
| Shared cold session lifetime spanning ORCL-01 then ORCL-03 | The composed CLI is the one place where a shared subprocess crosses predicate boundaries — a leak or double-kill here would affect both predicates' results |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02-05-01 | Tampering | verdict sidecar path derivation | mitigate | Sidecar path is a pure suffix-replace on the CLI's own input path argument, never joined with unsanitized fields read FROM the artifact's content (Task 2) |
| T-02-05-02 | Repudiation | `composeVerdict`'s persisted shape | mitigate | The full per-predicate outcome objects are always persisted alongside the derived `trueGreen` boolean — never collapsed to a bare boolean, preserving the design charter's "never compress away the ok/classification/false-green signal" guardrail (Task 1) |
| T-02-05-03 | Tampering | shared cold-session spawn in the composed path | mitigate | Reuses `spawnColdAgdaSession`'s existing argv-array spawn and `kill()`/`cleanup()` `finally`-block discipline already proven in Plans 02-01/02-03/02-04 — no new spawn code is introduced here (Task 2) |

</threat_model>
