`scripts/dogfood/dogfood-run.mjs`: `parseDogfoodArgv(argv)` (module-private, ~line 108) extracts `--manifest`/`--corpus-root`/`--run-id` via `argv[i+1]` with no value validation; a following flag token is silently accepted as a value, and a `--run-id` value is joined unvalidated at `const runDir = join(resolveRunsRoot(), runId);` (~line 245).

`scripts/dogfood/dogfood-wrapup.mjs`: `parseWrapupArgv(argv)` (module-private, ~line 434) takes `argv[0]` as `runId` unconditionally (a leading flag like `--rerun-n` would be accepted as the runId); joined unvalidated at `const runDir = join(resolveRunsRoot(), runId);` (~line 481). Its per-capture loop (~lines 499-533) has a `try { ... } catch (err) { ... }` block that dereferences `staged.stagedPath` FIVE times across both branches -- a `null`/malformed `stagedCaptures` element throws inside the catch too, escaping the loop entirely (no `wrapup-report.json` written, remaining captures unjudged).

`scripts/dogfood/install-dogfood-skill.mjs` (122 lines): `installDogfoodSkill({serverRepoRoot})` calls `symlinkSync(canonical, claudeLink, "dir")` in both the `existing === null` branch and the `relinked` branch WITHOUT first checking `canonical` exists -- a partial checkout gets a broken link reported as `"created"`. `scriptMain()` has no try/catch -- a thrown error (including any new check added here) escapes as a raw stack trace instead of a one-line stderr message + `process.exitCode = 1`.

`test/unit/tools/dogfood-install-skill.test.ts:60-71` ("SKILL.md is not gitignored" test): asserts only `expect(() => execFileSync("git", ["check-ignore", "-v", ...])).toThrow();` -- `git check-ignore` exits 1 for "not ignored" (the desired state) and 128 for a genuine failure (not a repo, bad path); both throw, so the test would pass even if git failed for the wrong reason.

Existing test files to extend (avoid creating overlapping new test files, avoid touching any file owned by plan `09-04` in the same phase): `test/unit/tools/dogfood-run-spawn-options.test.ts` already imports other named exports from `dogfood-run.mjs` -- the natural home for new `parseDogfoodArgv` tests. `test/unit/tools/dogfood-install-skill.test.ts` is NOT touched by plan `09-04` -- safe to edit here.
