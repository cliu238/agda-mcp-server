<objective>
Close the WR-01 durability edge named in the v1.0 audit: `resetRecordedActions()` in `src/tools/register-capture-session.ts` currently runs immediately after draining the buffer but BEFORE `writeFileAtomic` writes the staged artifact — so a write failure (disk full, permissions) in that window silently loses the drained action log with no artifact to show for it. Reorder it to run only after a successful write. While this plan already owns the file, also close two adjacent, unmapped P2 residuals from `01-06-PLAN.md` (the unexecuted Phase-1 gap plan) that the phase's own coverage note requires an explicit fix-or-record decision for: WR-12 (this test file still pollutes the shared, tracked `test/fixtures/agda/` fixture tree) gets FIXED here since it is the same file; WR-08 (stale `mergedArgv`) is verified ALREADY RESOLVED by Phase 2 and gets RECORDED, not re-fixed.

Purpose: A capture is often the only evidence a defect existed — losing it silently on a write failure defeats the entire Loop 2 premise. This is also the phase's `src-debt+tests` group, kept isolated to one file pair so it can run fully in parallel with the rest of the phase.
Output: A hardened `register-capture-session.ts` (durable write ordering, corrected comment), an isolated `register-capture-session.test.ts` (per-test temp sandboxes, new WR-01 regression test), and a recorded WR-08 closure decision in this plan's SUMMARY.
</objective>
