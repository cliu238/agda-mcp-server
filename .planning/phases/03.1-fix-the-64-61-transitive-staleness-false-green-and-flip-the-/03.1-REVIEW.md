## Summary

This phase fixes the #64/#61 transitive-staleness false-green by generalizing
`AgdaTransport`'s goal-terminus boolean into a `loadTerminusMode:
"metas"|"strict"|null` enum, extracting the tracking into a new pure sibling
`src/session/load-terminus-tracker.ts`, and flipping `runLoadNoMetas` to request
`{ loadTerminusMode: "strict" }` so a clean strict load is inferred from silence
after the widened idle window instead of resolving prematurely.

**The core mechanism is correct.** Every load-bearing property in the brief was
probed and verified against the code, not assumed:

- **Strict predicate is the widen-window design, not a fail-closed trap.**
  `isLoadTerminusSatisfied` returns `state.sawLoadError` alone for `"strict"`
  (load-terminus-tracker.ts:77-79). A clean goal-less strict load never satisfies
  the terminus, so it rides the widened idle window and completes on silence.
  Verified: unit test at load-terminus-tracker.test.ts:40-53 pins this, and it
  passes.
- **Metas mode is byte-for-byte unchanged.** The metas branch is exactly
  `sawLoadError || (sawInteractionPoints && sawAllGoalsWarnings)`
  (load-terminus-tracker.ts:80); the git diff shows `recordGoalTerminusResponse`
  and `sawGoalTerminus()` were lifted verbatim. `runLoad` still passes
  `{ awaitGoalTerminus: true }` which resolves to mode `"metas"`.
- **`createLoadTerminusState` resolution** `loadTerminusMode ?? (awaitGoalTerminus
  ? "metas" : null)` is correct; a bare `createLoadTerminusState()` yields
  `mode: null` (fast idle) — the "only load commands await a terminus" invariant
  holds (verified: load-terminus-tracker.test.ts:20-23).
- **Snapshot-hoist is semantically inert.** The single `const snapshot`
  (agda-transport.ts:478) feeds both `shouldResolveOnIdle` and
  `idleCompletionDelay` with identical values; `awaitGoalTerminus: mode !== null`
  equals the old `this.awaitGoalTerminus` on the metas path.
- **Terminus state cannot leak across commands** (the WR-08 class from Phase 2):
  `this.terminus` is reset at every entry point — `sendCommand` (:284),
  `sendFireAndForgetCommand` (:207), and `destroy` (:127). Commands are serialized
  on `commandQueue`, so no two `sendCommand`s share the transport concurrently.
- **Invariants intact:** agda-transport.ts is 497 lines (<= 500);
  load-terminus-tracker.ts is a class-less snapshot-object + pure-functions sibling
  (81 lines); no new IOTCM strings (`command("Cmd_load_no_metas", quoted(absPath))`
  routes through command-builder); single-`AgdaSession` unchanged; `runLoadNoMetas`
  emits only `ok-complete`/`type-error`. `tsc --noEmit` is clean; 36 unit tests
  pass.

No blockers. Three warnings concern residual robustness and test-value gaps that a
maintainer should sign off on consciously; two info items are readability/maintenance
nits.

### Warnings

#### WR-01: Stale doc comment on `CommandCompletionSnapshot.awaitGoalTerminus` now understates its meaning

**File:** `src/session/command-completion.ts:5-11`
**Issue:** The field doc still reads *"This command is a metas `Cmd_load` whose
goal-state terminus ... we must wait for. Set only on that path."* After this
phase the flag is populated from `this.terminus.mode !== null`
(agda-transport.ts:478), i.e. it is **also** true for a strict
`Cmd_load_no_metas`. The sibling `configuredGoalTerminusIdleMs` doc *was* updated
to describe both metas and strict (command-completion.ts:55-69), but this field's
doc was missed, leaving the two docs contradictory. A maintainer trusting this
comment would wrongly conclude strict loads keep the fast idle window and could
re-break the fix while "cleaning up". Correctness-adjacent because the whole phase
turns on this field covering strict.
**Fix:** Update the comment to describe both modes, e.g.:
```ts
/**
 * This command is a metas `Cmd_load` OR a strict `Cmd_load_no_metas`
 * whose load terminus we must wait for: metas waits for a positive
 * terminus (AllGoalsWarnings / InteractionPoints / Error); strict has
 * no positive success event and rides the widened window until
 * silence (or a DisplayInfo Error) settles it. Set on both load
 * paths; every other command leaves it false and keeps the fast idle.
 */
awaitGoalTerminus?: boolean;
```

#### WR-02: Strict path has no `sawLoadTerminus` backstop — residual, timing-dependent false-green under a compute gap larger than the widened window

**File:** `src/agda/session-load-impl.ts:201-257` (contrast `runLoad` at :92-97)
**Issue:** `runLoad` is double-guarded: the transport waits for the metas terminus
**and** `runLoad` rejects the result as `load-incomplete-no-terminus` when
`!parsed.sawLoadTerminus` (:92). `runLoadNoMetas` has **only** the transport's
widened-window silence — it cannot use the `sawLoadTerminus` check, because a clean
strict load legitimately emits no `InteractionPoints`/`AllGoalsWarnings`/`Error`, so
`parseLoadResponses` sets `sawLoadTerminus = false` for it (parse-load-responses.ts:193-197)
and the guard would false-RED every clean strict load. Consequence: if a delayed
type error arrives **later than `AGDA_MCP_LOAD_TERMINUS_IDLE_MS` (default 2000 ms)
after the last emitted response** — a post-type-check compute gap on a large module
before the `DisplayInfo Error` — the transport idle-completes with `[Status,
HighlightingInfo, ...]`, `parseLoadResponses` sees no error, and `runLoadNoMetas`
returns `ok-complete`: the exact #64/#61 false-green class, now merely narrowed
rather than eliminated. This is strictly better than pre-fix (which false-greened on
*any* truncation) and is inherent to the no-positive-terminus design; the timer also
resets on **every** response, so only a single silent tail-gap > 2 s reopens it, not
2 s of total compute. But the guarantee is materially weaker than the metas path and
is timing-dependent, and that asymmetry is undocumented.
**Fix:** No code change forces itself here, but make the residual risk explicit and
detectable rather than silent:
- Document in the `runLoadNoMetas` comment that strict success is single-guarded on
  silence and that `AGDA_MCP_LOAD_TERMINUS_IDLE_MS` must exceed the largest expected
  post-type-check→error gap for the target modules (surface the knob in README/env docs).
- Consider a `logger.warn` (or a soft diagnostic) when a strict load idle-completes
  having seen neither a `DisplayInfo Error` nor a `Status` epilogue, so operators can
  spot near-misses on large modules instead of silently trusting `ok-complete`.

#### WR-03: The `guard-no-metas-clean-load-under-fault-injection` matrix entry is non-discriminating — it passes with the strict fix reverted

**File:** `test/fixtures/capture-regression-matrix.json:31-53`
**Issue:** The guard asserts a mutation-less `agda_load_no_metas` on clean `Main.agda`
yields `ok-complete` under `AGDA_MCP_IDLE_COMPLETION_MS=1` /
`AGDA_MCP_POST_STATUS_IDLE_MS=1`. It does run a real load at the MCP boundary
(runner: capture-regression-runner.ts:82-100, no `mutation` ⇒ single call) and asserts
a real value — so it is not a *no-op*. But it does **not** discriminate this phase's
change:
1. A clean `Main.agda` classifies as `ok-complete` whether it resolves on the 1 ms
   short window (fix reverted, `mode=null`) or the 2 s widened window (fix present) —
   there is no error either way, and `parseLoadResponses` of even a partial `[Status]`
   stream still yields `success:true, goalCount:0 → ok-complete`. So the guard stays
   green with `{ loadTerminusMode: "strict" }` removed from `runLoadNoMetas`.
2. The "false-RED it guards against" cannot actually occur via the terminus predicate:
   `bumpIdleCompletionTimer` always arms the idle timer when `responseCount > 0`
   (`shouldResolveOnIdle`, command-completion.ts:129-133); the predicate only lengthens
   the *delay*, never blocks resolution — so a too-strict predicate would still resolve
   `ok-complete`, just slower. The real D-02 protection is the unit test
   `strict mode is NOT satisfied by the metas-style positive signal`
   (load-terminus-tracker.test.ts:40-53), and the real fix-lock is the **mutation**
   entry `issue-64-61-transitive-staleness` (matrix.json:2-30), which *does* flip to
   false-green `ok-complete` without the fix. This is therefore a test-value gap, not a
   coverage hole — the fix is still locked by the mutation entry.
**Fix:** Either (a) relabel the entry's intent to "coarse clean-load-under-fault-injection
sanity + env-plumbing check" (drop the "proves no false-RED / D-05 fix-lock" claim so a
future maintainer doesn't delete the unit test believing this entry covers it), or
(b) make it discriminating — e.g. a fixture/timing where premature short-window
resolution would drop a response that `ok-complete` depends on, so the widened window is
genuinely load-bearing for green.

### Info

#### IN-01: 247-character hoisted snapshot literal hurts readability

**File:** `src/session/agda-transport.ts:478`
**Issue:** The merged `const snapshot = { ... }` is a single 247-char line — roughly
3x the file's next-longest line (94) and a clear outlier by this file's own norms. The
hoist itself is correct (verified: both call sites receive the identical object), but
the inline five-field literal reads worse than the two wrapped literals it replaced.
The repo has no CI format gate and `.prettierrc` only sets `tabWidth`/`useTabs`, so this
will not break the build, but `npx prettier` would wrap it.
**Fix:** Wrap the object across lines (Prettier-style):
```ts
const snapshot = {
  sawStatusDone: this.sawStatusDone,
  responseCount: this.responseQueue.length,
  lastResponseKind: this.lastResponseKind,
  awaitGoalTerminus: this.terminus.mode !== null,
  sawGoalTerminus: isLoadTerminusSatisfied(this.terminus),
};
```

#### IN-02: Dual terminus API — boolean alias and enum coexist with one internal caller each

**File:** `src/session/load-terminus-tracker.ts:17-20`; callers at
`src/agda/session-load-impl.ts:86` (`{ awaitGoalTerminus: true }`) and `:204`
(`{ loadTerminusMode: "strict" }`)
**Issue:** `LoadTerminusOptions` exposes both the legacy `awaitGoalTerminus` boolean and
the new `loadTerminusMode` enum. Internally there is exactly one caller of each spelling,
and `{ awaitGoalTerminus: true }` and `{ loadTerminusMode: "metas" }` are synonyms. Two
ways to say "metas mode" invite drift over time. The alias is documented as intentional
backward-compat, so this is low priority.
**Fix:** Optionally migrate `runLoad` to `{ loadTerminusMode: "metas" }` for a single
canonical spelling and keep the boolean only if external/embedder callers rely on it
(none found in `src/`), or note in the interface doc that the boolean is retained solely
for external back-compat.
