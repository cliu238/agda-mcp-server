<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Maintainer's shell -> key registry file | Local, trusted operator input (person name) crosses into a persisted secret-bearing file |
| Key registry file -> ingest server (07-03, consumer) | A different process later reads this file to authenticate untrusted network requests |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-07-01 | Information Disclosure | scripts/team/issue-key.mjs registry writes | mitigate | Store sha256(key) only, never the raw key (D-13); raw key printed to stdout exactly once at issuance, never logged/persisted anywhere else |
| T-07-02 | Tampering | scripts/team/data/team-keys.json file permissions | mitigate | `chmod(keysPath, 0o600)` after every write — unreadable by other local users |
| T-07-03 | Spoofing | Stale/cached registry read allowing a revoked key to keep authenticating | mitigate | `readKeyRegistry` always re-reads from disk; no in-memory cache anywhere in this module — revocation is effective on the consumer's very next lookup |
| T-07-04 | Information Disclosure | Timing side-channel on Bearer comparison | mitigate | `crypto.timingSafeEqual`, never `===`, per D-13 |
| T-07-05 | Tampering | `.gitignore` omission accidentally commits the secret registry | mitigate | Explicit literal `.gitignore` entry added in Task 1, verified via grep in acceptance_criteria |
</threat_model>
