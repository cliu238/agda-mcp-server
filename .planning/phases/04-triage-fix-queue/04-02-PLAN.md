<objective>
## Phase Goal

**As a** maintainer (and the AI agents dogfooding this server), **I want to** have every captured defect persist, flow, and get prioritized/classified inside a durable in-repo queue, **so that** intake neither evaporates at session end nor outpaces fix throughput into a write-only graveyard.

*(Same phase-level user story as 04-01 — see that plan's objective for the full MVP_MODE adaptation note. This plan is the QUEUE-03 slice: after it lands, every new capture automatically carries a machine-readable classification of the Agda error it observed, ready for the queue's routing to consume, without an agent ever having to call agda_triage_error a second time by hand.)*

Wire the ALREADY-SHIPPED `classifyAgdaError()` classifier (and its `agda_triage_error` MCP tool, unchanged this phase) into the capture pipeline: every `agda_capture_session` call now derives a `TriageResult` from the last load-family action's recorded error (or `null` when there is none) and embeds it on the staged `CaptureArtifact`. Along the way, fix the fingerprint-fidelity gap RESEARCH.md's Pitfall 3 identified (the capture tool's current fingerprint call hardcodes a generic `affectedTool` and free-text `observed`, unlike `agda_bug_report_bundle`'s richer call to the same function) so a future live re-capture of a defect this milestone already hand-seeds (Plan 04-03) has a real chance of bumping recurrence instead of silently appearing as a new, disconnected entry.

Purpose: QUEUE-03 explicitly requires "feeding both capture-time classification and fix-queue routing" — this plan delivers the capture-time half; the queue-routing half is satisfied by Plan 04-03 carrying a `triageClass`/`triageConfidence` field per entry (populated by this same derivation for any FUTURE live capture).
Output: an additive, backward-compatible change to `src/agda/session-capture/artifact-types.ts` and `src/tools/register-capture-session.ts`, plus two new passing tests.
</objective>
