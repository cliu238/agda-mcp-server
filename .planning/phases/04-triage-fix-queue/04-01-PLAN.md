<objective>
## Phase Goal

**As a** maintainer (and the AI agents dogfooding this server), **I want to** have every captured defect persist, flow, and get prioritized/classified inside a durable in-repo queue, **so that** intake neither evaporates at session end nor outpaces fix throughput into a write-only graveyard.

*(Adapted from ROADMAP.md's outcome-technical Phase 4 goal line into user-story form per MVP_MODE — no scope invented, this restates the same 4 success criteria (QUEUE-01..04). This phase is infrastructure/scripts, not a UI feature: the "user" is the maintainer and the AI agents that operate the queue via scripts and file edits, so "vertical slice" here means "one requirement's worth of real, working capability," not a clickable screen. This plan is the FIRST slice: after it lands, the queue mechanism genuinely works end-to-end — a captured fingerprint can be upserted, bumped, and read back by capture-time dedup — even though the real 13-entry cargo doesn't land until Plan 04-03.)*

Deliver the queue's foundational engine: the zod-validated typed-loader contract (QUEUE-01's "single source of truth" shape), the intake upsert mechanism that turns a fingerprint-keyed record into either a fresh entry or a bumped-in-place existing one (never a duplicate — Pitfall 6's graveyard guard), and the repoint of Phase 1's CAP-02 dedup index so it reads the new durable queue file instead of the old gitignored, machine-local index.

Purpose: every other Phase-4 plan (seed data, capture-time classification wiring, priority/dashboard, GitHub mirror) either writes through this engine or reads the type contract it defines — this is the interface-first foundation, not a placeholder.
Output: `test/fixtures/fix-queue.{ts,json}`, `scripts/queue/intake.mjs`, a repointed `src/agda/session-capture/dedup-index.ts`, and passing tests for all three.
</objective>
