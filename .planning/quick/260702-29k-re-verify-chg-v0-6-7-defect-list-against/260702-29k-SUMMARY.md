- **Defect 1 verdict = "changed" (not "fixed")**: all 3 constructed repro shapes correctly detect the injected error on current main, but the underlying architectural gap CONCERNS.md names (`agdai-cache.ts` not walking the transitive import graph) is untouched by the commit (`e38f90a`) that most plausibly explains the improved behavior, and my fixtures are too small/fast to exercise the exact "large module, completion-detection idle-timer race" that empirically triggered the bug in CHG's real large corpus. A same-file-only repro cannot test the actual named defect mechanism, so two additional two-file repro shapes were added and run to reach an evidence-backed (not guessed) verdict, per the plan's own must-have truth requirement.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Added two transitive-dependency repro shapes for Defect 1, beyond the plan's literal single-file design**
- **Found during:** Task 1 (flagship false-green repro)
- **Issue:** The plan's Task 1 only specifies a same-file edit-and-reload repro (`FalseGreen.agda` edited in place). `.planning/codebase/CONCERNS.md` documents the actual #64/#61 defect as specifically a *transitive-dependency* staleness bug ("edit a dependency module's source after its interface has been loaded into the long-running interactive session, then reload only the top-level file"; "forceRecompile busts only the named file's own `.agdai`, not its transitive dependencies'"). A same-file-only repro tests a different (adjacent) mechanism and cannot, by itself, support a verdict on the actual named defect without guessing.
- **Fix:** Added two additional two-file repro shapes: (a) `tmp/chg-reverify/transitive/{Main,Dep}.agda` — a hard type error injected into the dependency's own body; (b) `tmp/chg-reverify/transitive2/{Main,Dep}.agda` — a signature-only change to the dependency that still typechecks cleanly on its own (the literal "record turned into a type synonym" shape CONCERNS.md names). Both were run through the same warm-session reload pattern and independently cross-checked against raw-`agda` ground truth.
- **Files modified:** `tmp/chg-reverify/transitive/*`, `tmp/chg-reverify/transitive2/*`, `tmp/run-transitive-staleness-repro.mjs`, `tmp/run-transitive-signature-repro.mjs` (all gitignored scratch, not committed)
- **Verification:** Both repro shapes produced real captured MCP envelopes (`transitive-staleness.json`, `transitive-signature-staleness.json`) and matching raw-`agda` ground truth (`transitive-raw-agda-{before,after}.txt`, `transitive2-raw-agda-{before,after}.txt`), all quoted in `.planning/research/CHG-REVERIFY.md`'s Defect 1 section.
- **Committed in:** `6aa28e4` (report only; the fixtures/drivers themselves are gitignored and not committed)

**2. [Rule 1 - Bug in test methodology] Reload between `agda_auto` calls to reopen the goal**
- **Found during:** Task 2 (`agda_auto`/`agda_give` repro)
- **Issue:** `agda_auto` with `writeToFile: false` was discovered to still close the goal in Agda's in-memory interactive top-level when a solution is found (`Cmd_autoOne` gives internally regardless of the MCP-layer file-write flag). The plan's literal driver-script design (baseline auto → flagged auto → give, all against a single `agda_load`) would fail at the second and third calls with `invalid-goal` because the baseline auto call already consumed goal 0.
- **Fix:** Inserted a fresh `agda_load` reload (the on-disk fixture file, untouched by `writeToFile: false`, still has the source hole) before each subsequent probe that needs an open goal.
- **Files modified:** `tmp/run-auto-give-repro.mjs` (gitignored scratch, not committed)
- **Verification:** `auto-give-repro.json` shows all 4 probes (`load`, `autoBaseline`, `autoWithFlags`, `giveTypeMismatch`) with valid, non-`invalid-goal` envelopes.
- **Committed in:** `6aa28e4` (report only)
