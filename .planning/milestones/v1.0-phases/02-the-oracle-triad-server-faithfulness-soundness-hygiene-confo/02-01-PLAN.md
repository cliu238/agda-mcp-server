## Phase Goal

**As a** maintainer or AI agent (Codex/Claude Code) dogfooding the Agda MCP server, **I want to** get
a captured session judged "true green" only when all three oracle predicates — the server-faithfulness
differential, the soundness-hygiene scan, and the conformance proxy — agree, **so that** a fresh
`agda` re-run's necessarily-insufficient pass is never mistaken for proof the server told the truth,
the fix was sound, and the right theorem was actually proved.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| AgdaSession live process state (`lastDispatchedLoadArgv`) -> `ReplayManifest.mergedArgv` | Crosses from transient in-process state into a persisted, later cold-replayed artifact; staleness here silently corrupts the ground truth Plan 02-03's differential pins to |
| Captured artifact's `manifest.agdaBinaryPath` -> `spawn()`/`execFileSync()` argv | Untrusted data (from a JSON file that may have crossed machines) feeding a child-process invocation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02-01-01 | Tampering | `src/agda/session.ts` + `session-process-lifecycle.ts` `lastDispatchedLoadArgv` fidelity | mitigate | Reset the field in `loadNoMetas()`, `resetFileBoundStateIfProcDied`, and `handleSessionProcessClose` — never in `invalidatePriorLoadState`/`resetProcBoundState`, which run mid-flow relative to a live `load()`'s pre-assignment — so a stale prior load's flags can never be stamped into a manifest this phase treats as authoritative (WR-08, Task 1) |
| T-02-01-02 | Tampering | `scripts/oracle/cold-agda-session.mjs` subprocess spawn | mitigate | `spawn(agdaBin, ["--interaction-json"], {...})` always uses the argv-array form, never a shell string interpolation, so an adversarial/corrupted `manifest.agdaBinaryPath` cannot inject shell syntax (Task 2) |
| T-02-01-03 | Denial of Service | `scripts/oracle/cold-agda-session.mjs` idle/hard-timeout handling | mitigate | Every `sendCommand()` call is idle-timed and (optionally) hard-timed; `kill()` is always reachable and idempotent, so a wedged cold Agda process cannot hang the oracle indefinitely (Task 2) |

</threat_model>
