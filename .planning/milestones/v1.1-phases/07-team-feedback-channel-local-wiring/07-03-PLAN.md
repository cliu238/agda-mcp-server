    createByteCounterGuard(maxBytes): return a `new Transform({ transform(chunk, enc, cb) { total += chunk.length; if (total > maxBytes) { cb(new SizeLimitExceededError(\`request body exceeded ${maxBytes} bytes\`)); return; } cb(null, chunk); } })` (Transform from "node:stream") with `total` closed over per-guard-instance (never module-level shared state).

    createIngestServer({storageDir, maxBytes, keysPath}): return `http.createServer(async (req, res) => { ... })` (createServer from "node:http"). Routing: parse `req.url` (a `new URL(req.url, "http://localhost")` is sufficient — no external URL parsing needed). If method GET and pathname "/healthz": respond 200 "ok", return immediately (no auth check). If NOT (method POST and pathname "/ingest"): respond 404, return. For POST /ingest: (1) read the Authorization header, extract the Bearer token via a `/^Bearer (.+)$/` match; if absent/malformed -> 401 + destroy req, return, BEFORE attaching any data listener. (2) person = verifyBearerToken(token, readKeyRegistry(keysPath)); if null -> 401 + destroy req, return. (3) runId = sanitizeRunId(req.headers["x-agda-mcp-run-id"]); if null -> 400 + destroy req, return. (4) contentLength = Number(req.headers["content-length"]); if Number.isFinite(contentLength) && contentLength > maxBytes -> 413 + destroy req, return (fast pre-check, before touching the body at all). (5) date = new Date().toISOString().slice(0,10) (UTC, computed server-side — never client-supplied). (6) relPath = join(person, date, \`${runId}.tar.gz\`); finalPath = resolveFileWithinRoot(storageDir, relPath) (wrap in try/catch for PathSandboxError -> 400, though person/date/runId are all already sanitized/server-derived so this should be unreachable — defense in depth, matching this project's own "reasoned even if not expected" commenting style). (7) mkdirSync(dirname(finalPath), {recursive:true}). tempPath = \`${finalPath}.tmp-${process.pid}-${randomUUID()}\` (randomUUID from "node:crypto", same-directory temp file so the final rename is atomic on one filesystem — mirrors writeFileAtomic's own temp-then-rename discipline without importing it, since this is a STREAMED write, not a string write). (8) try { await pipeline(req, createByteCounterGuard(maxBytes), createWriteStream(tempPath)) (pipeline from "node:stream/promises", createWriteStream from "node:fs"); await rename(tempPath, finalPath) (rename from "node:fs/promises"); respond 200 with JSON {ok:true, storedAt: relPath}; } catch (err) { best-effort unlink(tempPath); if (err instanceof SizeLimitExceededError) respond 413 (only if !res.headersSent); else respond 500 (only if !res.headersSent); log err to stderr either way. }

    Never buffer `req` into a Buffer/array anywhere in this handler — the pipeline is the ONLY place body bytes are touched.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Network (LAN/loopback) -> node:http handler | Untrusted request data (headers, body) crosses here |
| Authenticated request -> local filesystem write | Person/date/runId path components become an on-disk path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-07-10 | Spoofing | Forged/missing/revoked Bearer token | mitigate | `verifyBearerToken` (07-01) via `crypto.timingSafeEqual`, checked before any body read; registry re-read fresh per request so revocation is immediate |
| T-07-11 | Tampering | Path traversal via person/runId in the storage path | mitigate | `person` is ALWAYS derived from the authenticated registry entry, never a client header; `runId` is allowlist-validated (`^[A-Za-z0-9._-]+$`) before use; final path built via `resolveFileWithinRoot` |
| T-07-12 | Denial of Service | Oversized or slow-streamed body exhausting memory/disk | mitigate | `Content-Length` pre-check (fast path) + streamed `createByteCounterGuard` Transform (catches an absent/lying Content-Length) — both enforced BEFORE the body is fully buffered; temp file cleaned up on breach |
| T-07-13 | Tampering | Archive extracted/executed at ingest time | mitigate | This endpoint NEVER extracts — it only ever streams bytes to a temp file and renames; extraction is exclusively 07-05's sandboxed job |
| T-07-14 | Elevation of Privilege | Server accidentally bound beyond loopback, exposing it on the LAN/internet | mitigate | Default bind host `127.0.0.1`; a non-default `AGDA_MCP_TEAM_INGEST_HOST` is an explicit, documented opt-in only |
| T-07-15 | Repudiation | No record of accepted/rejected requests | accept | Out of scope for the ~100-line budget in v1.1 local mode; the stored path itself (person/date/runId) is the primary audit trail; revisit if abuse is observed |
</threat_model>
